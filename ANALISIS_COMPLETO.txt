  1. DESCRIPCIÓN GENERAL
  ---------------------------------------------------------------------
  MediaDock es un descargador de videos profesional con datos REALES
  desde yt-dlp. NO usa placeholders/demo.

  Frontend: React 18 + Vite 5 + TypeScript 5 + TailwindCSS 3 + shadcn/ui
  Backend: Express 4 + TypeScript 5 + yt-dlp + FFmpeg

  3. ARQUITECTURA BACKEND (en capas)
  ---------------------------------------------------------------------
  Capa 1: Routes → Enrutamiento (video.ts)
  Capa 2: Controllers → Validación Zod (videoController.ts)
  Capa 3: Services → Lógica de negocio (videoService.ts)
  Capa 4: Extractor → Strategy Pattern (registry.ts + extractores)
  Capa 5: Parser → Transformación de datos (metadata.ts)
  Capa 6: Cache → Memoria + disco (cache/index.ts)
  Capa 7: ErrorHandler → Middleware global (errorHandler.ts)


  4. FLUJO DE ANÁLISIS (POST /api/analyze)
  ---------------------------------------------------------------------
  Cliente → { url }
      │
      ▼
  [videoController] Valida con Zod urlSchema
      │
      ▼
  [VideoService.analyze(url)]
      │
      ├─ ¿URL en caché?
      │   ├─ Sí → devuelve { info, cached: true } (sin ejecutar yt-dlp)
      │   └─ No → continúa
      │
      ▼
  [ExtractorRegistry.getExtractor(url)]
      │  Busca extractor que cumpla canHandle(url)
      │
      ▼
  [YtDlpExtractor.extract(url)]
      │  Ejecuta: yt-dlp --dump-single-json --no-warnings --no-playlist {url}
      │
      ▼
  [parseYtDlpOutput(raw)]
      │  getBestThumbnail() → thumbnail más grande
      │  mapQualities() → agrupa por altura (2160p...Audio)
      │  getSubtitleLanguages() → extrae idiomas
      │  parseDuration() → "3:33"
      │
      ▼
  [VideoCache.set(url, info)]
      │  Guarda en Map (memoria) + .cache/{hash}.json (disco)
      │  TTL: 10 minutos
      │
      ▼
  Response → { info: VideoInfo, cached: false }


  5. FLUJO DE DESCARGA (POST /api/download)
  ---------------------------------------------------------------------
  Cliente → { url, qualityId }
      │
      ▼
  [videoController] Valida con Zod downloadSchema
      │
      ▼
  [VideoService.download(url, qualityId)]
      │
      ▼
  [ExtractorRegistry.download(url, qualityId)]
      │
      ▼
  [YtDlpExtractor.download(url, qualityId)]
      │  qualityId = "4029" (format_id numérico)
      │  o qualityId = "1080p" (se mapea a formato yt-dlp)
      │
      ▼
  [YtDlp.execStream(['-f', format, '-o', '-', url])]
      │  Stremear binario directamente
      │
      ▼
  [stream.pipe(res)]
      │  Content-Type: video/mp4
      │  Content-Disposition: attachment
      │
      ▼
  [Cliente recibe con axios onDownloadProgress]
      │  Barra de progreso + velocidad + ETA
      │  AbortController para cancelar


  6. SISTEMA DE EXTRACTORES (Strategy Pattern)
  ---------------------------------------------------------------------
  Interface Extractor:
    canHandle(url: string): boolean
    extract(url: string): Promise<ExtractResult>
    download(url: string, qualityId: string): Promise<NodeJS.ReadableStream>

  Extractores registrados (orden de prioridad):
    1. CuevanaExtractor → canHandle: detecta URLs de Cuevana
    2. YtDlpExtractor → canHandle: cualquier URL válida (universal)
    3. DemoExtractor → Solo si yt-dlp no está instalado

  ExtractorRegistry:
    register(extractor) → agrega a lista
    getExtractor(url) → busca el primero que cumpla canHandle
    extract(url) → delega al extractor correspondiente
    download(url, qualityId) → delega al extractor correspondiente


  7. SISTEMA DE CACHÉ
  ---------------------------------------------------------------------
  VideoCache:
    - Memoria: Map<string, { key, data, timestamp }>
    - Disco: .cache/{sha256[:16]}.json
    - TTL: 10 minutos (600,000 ms)
    - Limpieza automática cada 30 minutos
    - Hash: SHA-256 de la URL (primeros 16 chars hex)

  Flujo get(url):
    1. Buscar en memoria → si existe y no expiró → devolver
    2. Buscar en disco → si existe y no expiró → cargar a memoria + devolver
    3. Si expiró en disco → refrescar timestamp, devolver null
    4. Si no existe → devolver null

  Flujo set(url, data):
    1. Guardar en memoria
    2. Guardar en disco (silent fail si falla escritura)


  8. MANEJO DE ERRORES
  ---------------------------------------------------------------------
  errorHandler.ts (middleware global):
    - SyntaxError (JSON inválido) → 400 INVALID_JSON
    - ExtractorError → status + code del extractor
    - Otros → 500 INTERNAL_ERROR

  videoController.ts:
    - ZodError en analyze → 400 INVALID_URL
    - ZodError en download → 400 INVALID_REQUEST
    - ValidationError (calidad inválida) → 400 INVALID_QUALITY

  Errores conocidos (todos RESUELTOS):
    - yt-dlp no instalado → 503 EXTRACTOR_UNAVAILABLE
    - yt-dlp no encontrado → findBinary() escanea winget + PATH
    - via.placeholder.com caído → thumbnail real desde YouTube
    - Conflicto esbuild → se eliminó tsx, usa tsc + node
    - ERR_MODULE_NOT_FOUND → imports con .js
    - Sin progreso descarga → onDownloadProgress
    - Cancelar descarga → AbortController global
    - Sin caché → VideoCache memoria + disco
    - Sin datos reales → YtDlpExtractor + parser

  11. ESTADOS DE LA APLICACIÓN
  ---------------------------------------------------------------------
  useAppStore (Zustand):
    status: 'idle' | 'loading' | 'success' | 'error'

    idle:     Input vacío, título, footer
    loading:  Loading con 4 pasos animados
    success:  VideoPreview + DownloadSection + historial
    error:    ErrorState con mensaje clasificado

  Transiciones:
    idle → loading: usuario hace clic en "Analizar"
    loading → success: respuesta exitosa del backend
    loading → error: error del backend o red
    success → loading: usuario cambia URL y analiza de nuevo
    error → loading: usuario intenta de nuevo


  12. DOWNLOAD MANAGER (AbortController global)
  ---------------------------------------------------------------------
  downloadManager.ts:
    currentAbort: AbortController | null

    setAbortController(controller): Guarda el controller actual
    cancelDownload(): Aborta la descarga actual
    getAbortSignal(): Obtiene la señal para Axios

    Uso:
      Al iniciar descarga: new AbortController() → setAbortController()
      Al cancelar: cancelDownload()
      Al terminar: setAbortController(null)

  15. CÓMO FUNCIONA CADA ARCHIVO CLAVE
  ---------------------------------------------------------------------
  
  backend/src/index.ts:
    Crea Express app, aplica middleware global (helmet, cors, morgan, rate-limit),
    monta rutas /api, /health, y errorHandler. Puerto 3001.

  backend/src/routes/video.ts:
    Define POST /api/analyze y POST /api/download, conecta con controladores.

  backend/src/controllers/videoController.ts:
    Valida body con Zod schemas. analyzeVideo() llama VideoService.analyze().
    downloadVideo() obtiene stream y lo pipea a res con headers.

  backend/src/services/videoService.ts:
    ensureInit() registra extractores. analyze() revisa caché primero, 
    si no hay llama extractorRegistry.extract(). download() delega a 
    extractorRegistry.download().

  backend/src/extractor/registry.ts:
    Strategy Pattern. Register/extract/download delega al extractor 
    que cumple canHandle(url).

  backend/src/extractor/yt-dlp.ts:
    canHandle: cualquier URL válida. extract: ejecuta yt-dlp y parsea JSON.
    download: ejecuta yt-dlp con -f format_id y stremea stdout.

  backend/src/parser/metadata.ts:
    parseYtDlpOutput: normaliza el JSON de yt-dlp a VideoInfo.
    mapQualities: filtra, ordena y agrupa formatos de video+audio.

  backend/src/cache/index.ts:
    VideoCache con Map en memoria + archivos JSON en .cache/.
    Hash SHA-256 de URL como key. TTL 10 min.

  backend/src/middlewares/errorHandler.ts:
    Captura SyntaxError, ExtractorError, y errores genéricos.
    Responde con { error, code, status }.

  frontend/src/App.tsx:
    ErrorBoundary + Home component.

  frontend/src/pages/Home.tsx:
    VideoInput + AnimatePresence con Loading/VideoPreview/DownloadSection/
    ErrorState según status. Lazy loading con Suspense.

  frontend/src/store/useAppStore.ts:
    Zustand con persist. Estado completo de la app: status, videoInfo,
    error, downloadProgress, history, etc.

  frontend/src/hooks/useVideoInfo.ts:
    TanStack Query useMutation. onMutate → loading, onSuccess → success,
    onError → error + toast.

  frontend/src/services/api.ts:
    Axios instance con interceptors. analyzeVideo() y downloadVideo()
    con onDownloadProgress y AbortSignal.

  frontend/src/lib/downloadManager.ts:
    AbortController singleton. set/cancel/get para descargas.
